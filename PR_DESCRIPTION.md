# Pull Request: Add secure expense splitting to FinTrack

## Summary
Adds a shared-expense API with equal and custom participant allocations and a per-user net balance view. The Transaction module uses model, repository, service, controller and response DTO layers, owner-scoped access and request validation. Financial values use `BigDecimal`, and equal splits preserve the total by assigning any residual cents deterministically. This implementation uses H2 and demo HTTP Basic users for local assessment execution.

## Risks & Trade-offs
- H2 is in-memory and is not durable. Use PostgreSQL (or the approved production database), migrations, backups and transaction monitoring in a deployed environment.
- The demo in-memory user store is for local evaluation only. Production identity and secret management are out of scope.
- Current balance derivation treats the expense creator as the payer and assumes a single currency. FX conversion, settlement records, idempotency and immutable audit-ledger semantics require explicit product decisions.
